## 核心设计一：归因可以被逐字校验

RAG 公认的难点是"模型会不会编"。这个问题有一半可以确定性化——不判断答案"对不对"，
而判断它**有没有资格这么说**。回答不是一段散文，而是一组结构化断言，每条自带
chunkId 与逐字引文，由校验器执行四条铁律（纯字符串比对，零模型依赖）：

1. **禁止幻觉引用**：引用的片段必须真实存在于本次检索结果
2. **引文必须是原文字面子串**（仅归一化空白）——实测抓到模型把繁体"矽"顺手改成"硅"
3. **断言中的每个数字必须在被引片段中出现过**——数字幻觉专项
4. **证据不足必须拒答**；只能部分回答时必须在结构化 `gaps` 字段声明缺口

第 2 条的地基在切分层：每个片段保留原文字符区间，单测锁死
`chunk.text === doc.text.slice(start, end)`。不通过则带结构化原因**定向打回重排**。

诚实被定义为**一组可枚举的合法出口**：完整作答 / 拒答 / 部分作答+声明缺口——
"无法回答"与"只能回答一部分"都是合法结论（与 BrachioKey 的三态输出同构）。

## 核心设计二：检索是一条链路，不是一个模型

```
语料 → 切分（四种策略 A/B，保留字符区间）
   ├─ BM25（手写倒排索引 + 中文分词，0.3ms/题）
   └─ 向量（本地 bge-small-zh，暴力余弦，21ms/题）
        → RRF 融合（含单路保底名额）→ 候选池 50
        → cross-encoder 精排（本地 bge-reranker）→ top5
        → 生成（结构化断言）→ 归因校验 → 定向打回
```

一道贯穿全程的实弹题（"那种黑色的火山石头上面的小洞是怎么来的？"——通篇口语，
无一词与文档用语重合）走过的路：

| 环节 | 答案片段排名 | 结论 |
|---|---|---|
| BM25 | 第 137 | 查询无高信息量词，词法失灵 |
| 向量 | 第 43 | "小洞"被"黑色火山石头"的语义重心淹没 |
| RRF 融合 | 掉出前 50 | 融合奖励两路共识，挤掉单路独有的真答案 → 引入保底名额 |
| 精排（窗口 20） | 未进窗口 | "无损降本"砍掉了唯一靠精排翻案的题——**均值指标掩盖长尾** |
| **精排（全池）** | **第 2** | cross-encoder 逐词对照，认出"小洞"=="气孔" |

每一环都能单独杀死它，只有最后一环救活它。评测因此把**候选池召回率**（召回的 KPI：
别漏掉）与 recall@1（精排的 KPI：排第一）分开报——它是精排的天花板。

另一条负面结论同样有价值：**拒答无法用检索分数确定性化**。实测有答案题最低分 -1.67、
无答案题最高分 6.07（片段极其相关、只是不含答案）——相关性 ≠ 答案在不在里面，
任何阈值都会同时误拒与漏拒。拒答只能交给铁律 4 + 事后校验（`pnpm calibrate` 可复现）。

## 评测先行，且评测自身被审判

28 题金标准在写任何检索代码之前建好，期望行为三态标注（answer / refuse / partial），
自洽性 lint 进单测（goldDocId 必须存在、关键事实必须真的在标注文档里、出题人写错当场报警）。

开发全程"评测本身出错"**九次**，每次都以回归测试或结构化改造收场：语料数字写成汉字被
lint 抓获 → 语料扩大后金标准假设过时（引入事实级判定）→ 文档级/片段级名次混用 →
拒答阈值被校准数据推翻 → 片段 id 被误报为幻觉数字 → 二元判定漏掉"部分作答"这一最优行为 →
拒答题的"语料里没有"未随语料增长重查 → 部分作答的旧标签冤案 → 缺口声明正则漏检
（改为结构化 `gaps` 字段）。后四次全部发生在"诚实"的判定上——**诚实比正确难考**。
判定修对之后，成绩不仅上去了，**三轮方差归零**：此前的"抖动"多为判定歧义制造。

完整过程存档于 `docs/baseline-day*.md`（每日基线 + 失败分析 + 改判记录）。

## 快速开始

```bash
pnpm install
pnpm test        # 75 项单测，无需网络与 API key
pnpm chunks      # 语料 → 片段（打印长度分布）
pnpm eval        # 检索层评测：BM25 基线（全离线，毫秒级）

pnpm vectors                  # 本地算向量（首次下模型 ~100MB，可用 HF_ENDPOINT 镜像）
pnpm eval -- --compare        # BM25 / 向量 / 混合 / +精排 并排对照
pnpm sweep                    # 四种切分策略 × 两路检索 A/B
pnpm diag g12                 # 单题诊断：答案片段卡在链路哪一环
pnpm calibrate                # 拒答阈值校准（结论：阈值不可靠，含数据）

cp .env.example .env          # 只有生成层需要 API key（任意 Anthropic 兼容端点）
pnpm ask "玄武岩的二氧化硅含量范围是多少？"
pnpm eval:answer -- --repeat 3   # 生成层评测：诚实率/一遍过率，3 轮报均值±方差
```

## 语料与许可

- `data/corpus/`：12 篇合成教学语料（依据公开教科书知识撰写，CC0），入库——
  clone 即可跑通全流程与 CI，不依赖任何外部服务
- `data/corpus-wiki/`：可选的中文维基百科地学条目（CC BY-SA 4.0），不入库，
  `pnpm fetch:wiki` 自行抓取（118 条清单，限频 + 429 退避重试 + UA 标注）
- 金标准答案落在合成语料里；抓取语料把"干草堆"变大，让同一套题更难
- 教科书、行业标准、付费文献一律不入库
