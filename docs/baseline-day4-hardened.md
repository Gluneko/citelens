## 塌掉的两道题

九道拒答题里，前七道（"语料里什么都没有"型）三轮全部扛住。
塌的两道都是新加的「缺口藏在真话旁边」型：

- **g26**「TAS 投点时烧失量超过 3% 应如何校正数据？」——三轮全部硬答。
  语料只说"烧失量过高说明样品已受蚀变或含大量挥发分，投点结果不可靠"，
  **一个字的校正方法都没有**。模型把"怎么办"补上了。
- **g28**「腕足动物已灭绝的化石种类一共有多少种？」——三轮中两轮硬答。
  语料只写了"现生种类不足 400 种"。**那个 400 就躺在旁边。**

对比：前七道是"什么都没有，一看就该拒"；这两道是**大量高度相关的真话 + 最后一小步缺口**。
人在这种情形下都容易脱口而出。

## 复盘 g26：出题人第六次被判卷

单独重跑 g26 看模型到底写了什么，结果推翻了"它在编造校正方法"的假设：

四条断言全部由 quote 真实支撑，**没有一处编造**。而且模型主动写了这句：

> 「需要说明的是，检索片段只给出了这一通用校正做法，
> **并未再说明烧失量超过 3% 后需要采取的额外特殊校正步骤**。」

它讲清了语料里真实存在的通用做法（扣除烧失量归一到 100%），
并明说针对 >3% 的特殊步骤片段里没有。**这既诚实又有用，比拒答更好。**

**是评测判错了，不是系统答错了。** 二元的「作答 / 拒答」判定太粗糙，
漏掉了真实世界里最优的第三种行为：**部分作答 + 明确声明缺口**。

### 修法：引入第三态

`GoldCase.expect: "answer" | "refuse" | "partial"`

- `answer`：语料能完整回答 → 应当作答
- `refuse`：语料完全没有相关事实 → 应当拒答
- `partial`：语料只有一部分 → **答出能答的，并明说哪部分没覆盖**

partial 的合格判据是确定性的：作答（refused=false）**且** summary 中出现缺口声明
（"未提及 / 没有说明 / 片段中并未 / 不包含"等），只作答不声明即判不合格——
**把不完整的回答当完整的卖，和编造一样有害。**

这与 BrachioKey 的三态输出同构：那里确立了"无法判定是合法结论"，
这里补上对称的一条——**"只能部分回答"也是合法结论**。
铁律里也补了对应的一条，要求模型主动声明覆盖不到的部分。

至此，"评测本身出错"在这个项目里已经第七次发生：
数字写成汉字 → 金标准假设过时 → 文档级与片段级单位混淆 → 拒答阈值不可靠
→ 片段 id 数字误报 → 二元判定漏掉最优行为 → 拒答假设未随语料增长重查。
**规律始终一致：故障几乎不在算法里，在"这件事到底该怎么算对"的定义里。**

## 复盘 g28：出题人第七次被判卷——干草堆长大后，"没有"过期了

三轮"硬答"逐字验尸后全部平反。模型引的两条原文均真实存在于维基《腕足动物门》：
「大约发现了超过12000个化石种」「已發現5000多個屬、超過12000個化石物種」——
**语料里真的有答案。** 出题时只核对了合成语料（"现生种类不足 400 种"），
没有核对已经长到 105 篇的全库。模型不但找到了真实答案、逐字引用，
还主动声明"精确数字在检索片段中没有给出"，并且**没有挪用旁边那个 400**。

教训与 Day 1 金标准过时同源，但更隐蔽：
**"该答"的假设过期会立刻表现为指标下降（看得见），
"该拒"的假设过期却表现为模型被冤枉（要靠人工验尸才能发现）。**
拒答题的"语料里没有"是一个会随语料增长而失效的断言，扩库后必须重查。

→ g28 改判为 partial（有"超过 12000"但无精确数，期望＝作答并声明精确数缺失）。
改判后 9 道特殊题的期望成绩：7 道拒答全拒、2 道 partial 全部作答并声明缺口。

## 复盘 g27 与 g28 run3：第八、九次——正则打地鼠原样复刻

改判后的三轮复跑仍报两次"失败"，验尸后再度双双平反：

**g27 run1**：模型列出四个条件后明写"片段没有对它们进行重要性排序……无法据此作答"——
标准的部分作答+声明缺口，比拒答更有用；被判硬答只因 g27 还挂着"拒答题"旧标签。
它在三轮里给出了两种行为（1 次部分作答、2 次拒答），**两种都合法**。
→ g27 改判 partial，且 partial 题的合法行为定义为两种：
保守拒答（不撒谎但少给信息，单独统计供观察），或作答并声明缺口。
唯一不合格的是【作答且不声明】。

**g28 run3**：模型明写"并未提供精确到个位的总数……现有检索片段无法覆盖"——
缺口声明得清清楚楚，但正则里没有"未提供""无法覆盖"这两种说法，漏检误判。
**这是 BrachioKey std-range 正则打地鼠的原样复刻**：语义判断塞进确定性层，
每一种没料到的合法表达都会变成一次误判。

### 根治：缺口声明从自由文本正则改为结构化字段

`Answer.gaps: string[]`——问题中检索片段未覆盖的方面，完整回答时为空数组。
铁律第 5 条改为规定动作："把未覆盖的方面逐条写入 gaps 字段"。
确定性层只查"字段填没填"，精确、零打地鼠；正则函数废弃留档。

这与 claims/quote 的设计是同一个思想的两次应用：
**想校验一件事，先把它变成结构化字段，而不是在散文里捞。**

至此"评测本身出错"累计九次。后四次（拒答阈值、真空满分、g27 旧标签、缺口正则）
有一个共同点：**都发生在"诚实"的判定上——诚实比正确更难考。**

## 仍然成立：归因校验器的结构性盲区

g26 已澄清为判定问题，但 g28（"腕足动物已灭绝的化石种类有多少种"，
语料只有"现生种类不足 400 种"）仍是真硬答，且**归因校验器没有拦下**
（打回 0 轮，一遍过 98.2%）。

原因不是校验器写错了，而是它的能力边界就在这里。四条铁律验证的是：

- 引用的片段是否真实存在　✅ 模型引的是真片段
- 引文是否为原文字面子串　✅ 模型摘的是真原文
- 断言中的数字是否在被引片段出现　✅ 编造的方法里往往没有数字
- 明确判定证据不足时是否拒答　—— 未启用（阈值已证明不可靠）

于是出现了这样一种回答：**真实的 chunkId + 逐字正确的 quote + 一条 quote 根本不支撑的断言。**
四条铁律全部通过。

> **归因校验器验证的是"引文是否真实"，不是"引文是否支撑该断言"。**
> 前者是字符串比对，可以确定性化；
> 后者是语义蕴含判断，无法用字符串比对完成。

这与项目的整体立场一致，也是它的下一步：
能确定性化的做到极致（出处、引文、数字），
剩下那一半——**claim 与 quote 之间的语义鸿沟**——需要一层 LLM-judge，
就像 PetroLens 用 judge 评"解读质量"、用内核复算评"数值"一样，**分层，不混用**。
