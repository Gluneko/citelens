## 四条结论

**一、精排是唯一能提升 recall@1 的手段，代价是四千倍延迟。**
recall@1 78.9% → 84.2%，MRR 0.844 → 0.895；耗时 0.3ms → 1227ms。
cross-encoder 把问题与文档拼在一起逐词对照，这正是它准的原因，也是它慢的原因——
每个候选都要跑一次完整前向，无法预计算。

**二、精排候选数是纯成本旋钮，砍掉一多半几乎无损。**
全池精排 3598ms/题 → 只精排前 20 为 1219ms/题（省 66%），五项指标一分未变。
`liftedFrom` 显示被顶进前五的候选多在前 20 位，后 30 条基本是白烧。

**三、RRF 融合会把「只有单路能找到的答案」挤出候选池。**
g12 的答案在向量单路排第 17，融合后掉出前 50——候选池召回率从 100% 掉到 94.7%。
RRF 只奖励"两路共识"，另辟蹊径的那一路会被系统性压制。
对策：单路保底名额（每路前 N 名强制入池，替换尾部而非扩容）。

**四、候选池召回率必须与 recall@1 分开看。**
向量单路 recall@1 只有 63.2%（最低），候选池召回率却是 100%（最高）——
它"捞得到但排不好"，正是精排的理想搭档。
把两段混在一个数字里，就永远说不清是召回漏了还是排序错了。
