# Day 4 实弹：归因校验器首跑（2026-08-26）

配置：向量召回 50 + 全池 cross-encoder 精排 → top5 → DeepSeek 生成 → 归因校验 → 定向打回
问题：「玄武岩的二氧化硅含量范围是多少？」｜结果：**R0=1 错误 → R1=0 错误**｜$0.2051

## 校验器抓到的真实幻觉

第 0 轮 `claims[2]` 被 `quote.not-substring` 拦下：

- 模型写的引文：「其中二氧化**硅**含量最多，约占45%~52%左右」
- 维基原文：　　「其中二氧化**矽**含量最多，约占45%~52%左右」

模型顺手把繁体用字"矽"规范化成了简体常用字"硅"。**读起来毫无破绽，但已经不是原文。**
打回一轮后照抄原文，通过。

这正是字面子串校验的价值：**引文一旦允许"差不多"，溯源就失去全部意义**。
语义级的"意思对不对"要靠人或 judge，但"是不是原话"是纯字符串比对——
这就是归因可以被确定性化的那一半。

## 校验器自身的误报（第五次应验）

同一轮里 `summary.unclaimed-number` 报出「020、0、0、020、2、1」——
全部来自 summary 中规范标注的片段 id（如 `wiki-020-玄武岩#0`）。
**模型每一次规范引用，反而触发一次告警。**

修法：统计前先剔除所有片段 id（长 id 优先替换，避免短 id 是长 id 前缀时留下残片），
并加回归测试锁定：剔除后真正未溯源的数字（如凭空出现的密度 2.9）仍须报出。

"校验器误报也是故障"——误报不只是噪音，它会让人开始无视告警，
最终把真错误一起漏掉。

## 精排分数作为拒答判据的证据

同一批候选，两种打分方式的分布：

| 名次 | 余弦（bi-encoder） | 精排（cross-encoder） |
|---|---|---|
| 1 | 0.601 | 5.94 |
| 2 | 0.598 | 5.24 |
| 3 | 0.595 | 4.38 |
| 4 | 0.595 | 4.11 |
| 5 | 0.592 | 2.34 |

余弦全挤在 0.009 的区间内，**无法设阈值**；精排拉开 3.6 分跨度，第 5 名明显掉队。
拒答判据必须建立在精排分数上，这是 Day 3 的观察在 Day 4 的兑现。
