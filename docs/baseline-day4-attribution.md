# Day 4 实弹：归因校验器首跑（2026-08-26）

配置：向量召回 50 + 全池 cross-encoder 精排 → top5 → DeepSeek 生成 → 归因校验 → 定向打回
问题：「玄武岩的二氧化硅含量范围是多少？」｜结果：**R0=1 错误 → R1=0 错误**｜$0.2051

## 校验器抓到的真实幻觉

第 0 轮 `claims[2]` 被 `quote.not-substring` 拦下：

- 模型写的引文：「其中二氧化**硅**含量最多，约占45%~52%左右」
- 维基原文：　　「其中二氧化**矽**含量最多，约占45%~52%左右」

模型顺手把繁体用字"矽"规范化成了简体常用字"硅"。**读起来毫无破绽，但已经不是原文。**
打回一轮后照抄原文，通过。

这正是字面子串校验的价值：**引文一旦允许"差不多"，溯源就失去全部意义**。
语义级的"意思对不对"要靠人或 judge，但"是不是原话"是纯字符串比对——
这就是归因可以被确定性化的那一半。

## 校验器自身的误报（第五次应验）

同一轮里 `summary.unclaimed-number` 报出「020、0、0、020、2、1」——
全部来自 summary 中规范标注的片段 id（如 `wiki-020-玄武岩#0`）。
**模型每一次规范引用，反而触发一次告警。**

修法：统计前先剔除所有片段 id（长 id 优先替换，避免短 id 是长 id 前缀时留下残片），
并加回归测试锁定：剔除后真正未溯源的数字（如凭空出现的密度 2.9）仍须报出。

"校验器误报也是故障"——误报不只是噪音，它会让人开始无视告警，
最终把真错误一起漏掉。

## 拒答阈值：一个被实测推翻的设计

初始设想是"精排分数比余弦分得开，所以可以拿它当拒答阈值"。
分得开是真的（同批候选：余弦 0.601~0.592 挤在 0.009 内，精排 5.94~2.34 跨 3.6 分），
但**"分得开"不等于"能分对"**。

用 24 题（19 有答案 / 5 道对抗拒答题）实测 top1 精排分数：

| | 最低 | 中位 | 最高 |
|---|---|---|---|
| 有答案（19 题） | **-1.67**（g12） | 5.94 | 8.20 |
| 拒答题（5 题） | -3.09 | -1.23 | **6.07**（g23） |

两组严重重叠：10 道有答案题与 3 道拒答题落在重叠区，**任何阈值都同时产生误拒与漏拒**。

### 决定性反例：g23

「CIPW 标准矿物计算的四位提出者分别叫什么名字？」top1 = **6.07**，
高于 19 道有答案题中的 10 道。

原因很简单也很致命：语料里 `cipw-norm` 那段**确实高度相关**——它就在讲 CIPW，
还写了"四位学者姓氏首字母"。cross-encoder 判它极相关，判得没错。
**它只是没有答案。**

> **相关性 ≠ 答案在不在里面。**
> 检索分数衡量的是"这段文字和问题有多像"，
> 而拒答需要的是"这段文字能不能支撑一个具体结论"——这是两个不同的问题。

替代判据"top1 与 top5 的落差"同样破产：
有答案平均 6.29、拒答题平均 3.21 看似可分，但 g12（有答案）落差 1.66、
g23（拒答）落差 9.83，正好反着来。

### 实测确认的误拒

给 g12 加上 `--refuse-below 0`（其 top1 = -1.67）后，模型被强制拒答。
值得注意的是：**它为这个被强加的结论编出了一套听起来很有道理的理由**
（"黑色火山岩有玄武岩、黑曜岩、凝灰岩多种，无法唯一确定"）。
不加阈值时，同一模型、同一批片段，它一遍过答对了。

这是个独立的警示：**模型会为任何被强加的结论生成合理化解释**。
所以"模型说得有道理"不能作为该结论正确的证据。

### 结论

拒答无法被检索分数确定性化。它只能靠：
1. **铁律 4**：把"证据不足必须拒答"写进系统提示，交给模型判断（本项目默认）
2. **归因校验器事后核对**：拒答时不得同时给断言；作答时每条断言必须逐字溯源

这与项目的整体立场一致：**能确定性化的部分做到极致（引文、数字、出处），
不能确定性化的部分诚实标出来，不假装它可以。**
