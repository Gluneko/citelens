## 四、三条负结果（与正结果同等重要）

1. **拒答无法用检索分数确定性化。** 有答案题最低分 -1.67，无答案题最高分 6.07
   （片段极其相关、只是不含答案）。相关性 ≠ 答案在不在里面。
2. **803 片段的规模不需要向量库。** 实测：暴力 0.41ms/查询；8 千条时 HNSW 加速 18 倍
   （召回 95%），4 万条时 107 倍（召回 89%，建索引 17.7s）。速度是拿精度换的，
   而在小规模上无东西可换。
3. **密语料上"标题提及"图谱是冗余信号。** 105 节点 724 边、枢纽文档连 73 边——
   在百科型语料上，造成图谱边的词汇重合恰恰也造成 BM25 命中，两个信号高度相关。
   图谱扩展的增量场景（第二跳与查询零词汇重合）在此语料上未出现。

## 五、评测自身的审判记录（九次 + 一次预期落空）

lint 抓获语料数字体例 → 语料扩大金标准过时 → 文档/片段级名次混用 → 拒答阈值被校准推翻
→ 片段 id 误报 → 二元判定漏掉最优行为 → 拒答假设未随语料重查 → partial 旧标签冤案
→ 缺口正则漏检（改结构化字段）；另有一次设计预期落空：g29 按图谱题设计，
实测是排序题（如实分开记账——预期错了不是判定错了）。

后四次判定错误全部发生在"诚实"上：**诚实比正确难考**——正确只有一种，
诚实的合法表达有无数种。出路不是更聪明的正则，而是把期望行为变成结构化规定动作。
判定修对后，三轮方差归零：**此前的"抖动"多为判定歧义制造，不是模型行为随机。**

## 六、工程纪律沉淀（可直接搬去下一个项目）

- 评测先行：标尺早于代码；出题人同样被 lint 审判
- 断言分层：确定性层只考规定动作（结构化字段），语义质量留给 judge/人
- 辅助信号纪律：改写、保底、图谱——只许提名候选，不许改选票（排序权只归精排+原始问题）
- 指标分层：候选池召回率（别漏）与 recall@1（排对）分开报；降本决策看逐题明细，不看均值
- 运行器纪律：逐题容错、致命错误优雅中止保成绩、断点续跑、空集不报真空满分
